## 一、项目概述

- **定位**：求职用的个人网站。首页展示学习成果，三大模块 = **简历 / 笔记 / 用户**，目标是公网可访问。
- **现状**：全栈已打通（前端 5180 → 代理 → 后端 8080 → MySQL），多用户隔离、讨论广场、AI 助手（知识库问答）均已落地。

### 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue 3.5 + TypeScript + Vite 8 + Vue Router 5 + Pinia 4；Markdown 用 `markdown-it` + `highlight.js` |
| 前端测试/规范 | Vitest（jsdom）+ Cypress；oxlint + oxfmt + eslint；Node `^22.18.0 \|\| >=24.12.0` |
| 后端测试 | JUnit 6 + Mockito（`mvn test`） |
| 后端 | Spring Boot **4.0.9-SNAPSHOT** + MyBatis 4.0.1 + MySQL 8（ngram 全文检索） + BCrypt + jjwt 0.12.6 + Lombok |
| 大模型 | DeepSeek（OpenAI 兼容协议），Key 走环境变量，未配置时功能降级不阻塞 |

### 目录结构

```
back/InterViewBacked/           后端工程（包名 com.wjh.interviewbacked）
front/InterviewProjectProject/  前端工程

```

## 三、关键设计

### 3.1 数据归属与可见性（本项目最重要的部分）

- 每张业务表都有 `user_id`，列表查询**强制带归属**（缺失时返回空集，绝不退回全表）
- 写操作先校验归属，越权返回 403；详情接口由 `assertVisible()` 统一收口
- `note.visibility`：`0` 私有 / `1` 讨论广场公开 / `2` 链接分享（预留）
- 标签云、首页统计同样按 scope 收口，避免"私有笔记的标签也算进公开统计"

### 3.2 前端分层与状态

- **service 层抽象**：页面永不直接 `import src/data/`，一律走 `src/services/`（note / resume / user / assistant / analysis），后端接入时只替换实现
- **统一 HTTP 客户端** `utils/http.ts`：注入 JWT、解包 `ApiResult<T>`、`code!==0` 抛 `ApiError`、401 自动清登录态
- **按用户隔离的缓存**：store 记 `ownerId = 用户 id`，账号切换/登出自动重载或清空（`useNoteStore.myNotesOwnerId`、`useResumeStore.loadedFor`）
- **组件与样式约定**：组件名带 `Component` 后缀；样式三层分离（`global.css` → `common/` → `components/`）；`<script lang="ts">`；复用两次以上就往上层抽

### 3.3 AI 助手（RAG）

```
提问 → 落库 → 全文检索召回 Top5（WHERE user_id=?）→ 拼 Prompt（笔记正文截断 + 最近 6 条历史）
     → DeepSeek 作答 → 落库并保存引用 → 前端渲染「引用了 N 篇笔记」
```

选型取舍：**MySQL 全文检索**而非向量库（几十～几百篇笔记够用，零新增组件）；
将来换向量检索只需替换 `AssistantServiceImpl.recall()`，Prompt 组装层不动。

### 3.4 数据模型（13 张表）

```
user / resume
note / note_content(正文垂直拆分 + 全文索引) / tag / note_tag_rel / note_share
note_analysis(单篇分析结果) / async_task(异步任务)
chat_session / chat_message(AI 助手会话与消息，refs 存引用)
file(对象存储预留)
```

乐观锁：`note.version` / `resume.version`，更新带 `WHERE version = ?`，冲突返回 409。

## 四、接口清单（26 个，详见 `3.接口文档.md`）

| 分组 | 数量 | 代表接口 |
|---|---|---|
| 笔记 `/api/notes` | 9 | `GET ?scope=mine\|plaza`、`GET /{id}`、`POST`、`PUT`、`DELETE`、`PATCH /{id}/pin`、`PATCH /{id}/plaza`、`PATCH /{id}/views`、`GET /tags` |
| 分析 `/api` | 3 | `POST /notes/{id}/analyze`、`GET /notes/{id}/analysis`、`GET /analysis/tasks/{taskId}` |
| AI 助手 `/api/assistant` | 5 | `GET /sessions`、`POST /sessions`、`DELETE /sessions/{id}`、`GET /sessions/{id}/messages`、`POST /sessions/{id}/ask` |
| 用户 | 5 | `POST /auth/login`、`POST /auth/register`、`POST /auth/logout`、`GET /auth/me`、`PATCH /users/me` |
| 简历 `/api/resumes` | 4 | `GET /`（快照）、`POST`、`PUT /{id}`、`DELETE /{id}` |

安全约定：GET 默认公开，需要登录的 GET（助手、广场之外的私有数据）由 Controller 手动判空抛 401；
所有写操作与私有数据读取都校验归属。

## 六、如何运行

**一键（推荐）**：双击 `scripts/start-dev.bat`（起后端 8080 + 前端 5180 并开浏览器）。

**手动**

```bat
:: 后端（JDK 21 + 本机 MySQL）
set JAVA_HOME=C:\Program Files\Java\jdk-21
cd back\InterViewBacked
mvn.cmd spring-boot:run -Dspring-boot.run.arguments="--server.port=8080"
```

```bash
# 前端
cd front/InterviewProjectProject
npm install --legacy-peer-deps   # oxlint 有 peer 冲突
npm run dev                      # 端口 5180（strictPort，被占用会直接报错）
```

浏览器开 `http://localhost:5180`，演示账号 `admin / 123456`（⚠️ 上线前必改，见 `7.部署上线方案.md` 安全清单）。
链路：浏览器 → 5180（Vite `/api` 代理）→ 8080（Spring Boot）→ MySQL。

**上线**：照 `开发文档/7.部署上线方案.md` 执行（JDK21 + Nginx + MySQL8 + systemd + certbot）。
