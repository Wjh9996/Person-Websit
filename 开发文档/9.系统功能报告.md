# 个人网站系统功能报告

> 本报告基于当前代码实况盘点（2026-09-18），覆盖前端、后端全部功能设计与使用技术。
> 数据口径：后端 72 个 Java 类 / 8 个 Mapper XML / 13 张表 / 28 个接口；
> 前端 25 个 `.vue` / 30 个 `.ts` / 16 个样式文件 / 23 条单测。

---

## 一、系统概览

### 1.1 定位

求职用的个人网站：首页展示学习成果，核心是**简历、笔记、用户**三大模块，并叠加两项 AI 能力
（单篇笔记智能分析、基于自己笔记的知识库问答）。系统已从"个人作品集"演进为**多用户隔离的站点**：
每个用户拥有自己的简历与笔记，可选择把笔记发布到**讨论广场**供所有人浏览。

### 1.2 部署形态

```
浏览器 ──► https://domain（Nginx 静态资源）
            │
            └─ /api/* ──► Spring Boot(:8080) ──► MySQL 8
                              │
                              └─► DeepSeek（OpenAI 兼容 /chat/completions）

本地开发：浏览器 → Vite(:5180) → /api 代理 → Spring Boot(:8080) → MySQL
```

### 1.3 模块一览

| 模块 | 关键能力 | 权限 |
|---|---|---|
| 用户 | 注册/登录/JWT/个人资料 | 公开浏览 + 登录后编辑 |
| 简历 | 多份简历切换、在线编辑、游客浏览 | 同上 |
| 笔记 | Markdown 编写、分类标签、置顶、搜索、阅读数 | 我的笔记需登录 |
| 讨论广场 | 公开笔记聚合、作者署名 | 完全公开 |
| AI 分析 | 单篇笔记摘要/关键词/分类/知识点 | 需登录 |
| AI 助手 | 基于自己笔记的多轮问答（RAG）+ 引用溯源 | 需登录 |

### 3.3 状态管理（3 个 store）

| store | 关键设计 |
|---|---|
| `useUserStore` | 登录态、profile、login/register/logout、`refresh()` 用令牌换 `/api/auth/me` |
| `useNoteStore` | **双份数据**：`myNotes`（本人）/ `plazaNotes`（广场）；`setScope()` 切换；`notes/tags/loading/loaded` 为当前 scope 的只读视图；**`myNotesOwnerId` + `watch(profile.id)`** 保证换账号/登出时缓存失效；筛选、统计、上下篇均由此派生 |
| `useResumeStore` | 简历快照与导航项；`loadedFor` 记**用户 id**（而非"是否登录"），账号切换自动重载 |

### 3.4 路由与权限

- 路由守卫：`meta.requiresAuth` 的页面（`/notes`、`/profile`、`/notes/create`、`/notes/:id/edit`、`/assistant`）未登录跳登录页并带 `redirect`
- 写操作守卫：`useAuthGuard().requireLogin()`——未登录弹提示且**不发起请求**
- 详情页操作按钮按 `isOwner`（`note.authorId === 当前用户 id`）显隐，而不是只看"是否登录"
- 路由顺序：`/notes/create` 必须排在 `/notes/:id` 之前

### 3.5 服务层与 HTTP

- 页面永不直接 `import src/data/`，一律走 `src/services/`（note / resume / user / analysis / assistant）
- `utils/http.ts`：统一 `fetch` 封装，注入 `Authorization: Bearer`，解包 `ApiResult<T>`，`code!==0` 抛 `ApiError`，401 自动清登录态
- 开发环境走 Vite `/api` 代理避免跨域；生产可设 `VITE_API_BASE_URL`

### 3.6 Markdown 与工具

- `utils/markdown.ts`：`renderMarkdown()` 产出 HTML + 目录结构、`excerpt()` 摘要、`readingTime()` 阅读时长；关闭 `html:true` 防 XSS
- `utils/datetime.ts`：`fromNow`、`formatDate`、`formatDateTime`
- `utils/storage.ts`：localStorage 读写封装（带前缀与降级）
- `utils/errorMessage.ts`：统一错误文案提取

### 3.7 样式体系（16 个 CSS）

`global.css`（重置） → `common/`（buttons / cards / badges / stats） → `components/`（header、footer、notes、editor、markdown、toc、usermenu、login-required、resume、**assistant**）

## 四、后端功能设计

### 4.1 分层结构

```
controller（6） → service（5 接口 + impl） → mapper（12 个接口 + 8 个 XML） → entity（12）
common：ApiResult / JwtUtil / JacksonUtils / HashUtils / LlmProperties
component：LlmClient（DeepSeek 调用）
config：WebConfig（CORS + 拦截器） / JwtInterceptor / DataInitializer
exception：BusinessException / GlobalExceptionHandler
```

### 4.2 接口清单（26 个）

**笔记 `/api/notes`（9）**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/notes?scope=mine\|plaza` | 我的笔记（需登录）/ 讨论广场（公开） |
| GET | `/api/notes/{id}` | 详情；私有笔记非作者 → 403 |
| POST | `/api/notes` | 新建（`toPlaza` 决定是否发广场） |
| PUT | `/api/notes/{id}` | 更新（乐观锁 + 内容去重 + 可见性调整） |
| DELETE | `/api/notes/{id}` | 软删除 |
| PATCH | `/api/notes/{id}/pin` | 置顶切换 |
| PATCH | `/api/notes/{id}/plaza?toPlaza=` | 发布/收回广场 |
| PATCH | `/api/notes/{id}/views` | 阅读数 +1 |
| GET | `/api/notes/tags?scope=` | 标签云（按 scope 收口） |

**AI 分析（3）**：`POST /api/notes/{id}/analyze`（触发）、`GET /api/notes/{id}/analysis`（结果）、`GET /api/analysis/tasks/{taskId}`（轮询）

**AI 助手 `/api/assistant`（5）**：`GET /sessions`、`POST /sessions`、`DELETE /sessions/{id}`、`GET /sessions/{id}/messages`、`POST /sessions/{id}/ask`

**用户（5）**：`POST /auth/login`、`POST /auth/register`、`POST /auth/logout`、`GET /auth/me`、`PATCH /users/me`

**简历 `/api/resumes`（4）**：`GET /`（快照）、`POST`、`PUT /{id}`、`DELETE /{id}`

### 4.3 鉴权与权限

- `JwtInterceptor`：登录/注册/登出公开；**GET 默认公开**，写接口 + `/api/auth/me`、`/api/users/**` 需令牌；任何请求若带合法令牌都解析出 `userId` 放进 request
- **需要登录的 GET**（助手全部接口）用 `@RequestAttribute(value="userId", required=false)` 取身份后手动判空抛 401
- 归属校验：写操作与私有数据读取一律校验 `user_id`，越权抛 403
- 可见性收口：`NoteServiceImpl.assertVisible()`——广场放行，私有必须作者本人
- 列表兜底：`listNotes` 的 `user_id` 条件为**必填**，缺失时 SQL 走 `AND 1 = 0` 返回空集，绝不退回全表

### 4.4 数据访问

- MyBatis XML 管理 SQL；`map-underscore-to-camel-case` 自动映射
- **乐观锁**：`note.version` / `resume.version`，`UPDATE ... WHERE version = ?`，0 行 → 409 冲突
- **内容去重**：`content_hash`（MD5）比对，无变化不写库、不 bump 版本
- **全文检索**：`MATCH(title, summary)` + `MATCH(content)`（ngram），支撑列表搜索与 AI 召回；索引不可用时 `LIKE` 兜底
- **垂直拆分**：列表只查 `note`（不含正文），详情/编辑/AI 才取 `note_content`

### 4.5 异步任务

`async_task` 表 + Spring 自动配置的 `TaskExecutor`（**不用 `@Async`，避免自调用代理失效**）：
触发即建任务 → 后台执行 → 更新 success/failed，前端 1.5s × 40 轮询。未来可平换 MQ 消费者。

### 4.6 AI 能力

| 能力 | 实现 |
|---|---|
| 单篇分析 | 4 种类型（summary/keywords/category/knowledge），强制 `response_format: json_object`，结果存 `note_analysis`；正文变更（`content_hash`）自动 `status=0` 失效 |
| 知识库问答 | 提问 → 落库 → 全文检索召回 Top5（`WHERE user_id=?`）→ 拼 Prompt（正文截断 2500 字 + 最近 6 条历史）→ DeepSeek 作答 → 落库并保存引用 → 返回 answer + refs |
| 追问优化 | 问题 < 12 字时召回关键词拼接"上一轮问题"；Prompt 允许在参考笔记不相关时依据历史对话作答 |
| 降级 | 未配 `LLM_API_KEY` 时抛明确异常，任务标记 failed，不影响其他功能 |

### 4.7 初始化与异常处理

- `DataInitializer`：幂等播种演示账号 `admin/123456`（⚠️ 上线前必须修改，见 `7.部署上线方案.md` 安全清单）、7 篇笔记、3 份简历
- `GlobalExceptionHandler`：业务异常 → 对应 code/message；参数校验 → 400；未捕获 → 500
- `ApiResult<T>{code,message,data}` 统一包装，`code=0` 成功

## 六、核心业务流程

**① 登录**：提交账号密码 → BCrypt 比对 → 签发 JWT（7 天）→ 前端存 token+profile → 各 store 按 `ownerId` 重载数据。

**② 写笔记并发布**：编辑器 Markdown 预览 → 勾选"发布到讨论广场" → `POST /api/notes`（`toPlaza`）→ 后端按 JWT 归属写入 → 前端同时更新 `myNotes` 与（若公开）`plazaNotes`。

**③ 广场浏览**：游客打开 `/plaza` → `GET /api/notes?scope=plaza` → 后端过滤 `visibility=1` 并 JOIN 作者昵称 → 卡片展示署名 → 点进详情（公开放行）。

**④ AI 问答**：选会话 → `POST /ask` → 后端落用户消息 → 召回（仅本人笔记）→ 拼 Prompt → DeepSeek → 落助手消息（含 refs）→ 前端渲染回答 + "引用了 N 篇笔记"卡片（可点回原文）。

**⑤ AI 分析**：详情页点"✨ AI 分析" → `POST /analyze` 返回 taskId → 前端轮询 → 成功后 `GET /analysis` 展示摘要/关键词/分类建议/知识点。

## 七、安全设计

| 层面 | 措施 |
|---|---|
| 认证 | JWT（HS384，jjwt），7 天有效；401 自动清登录态 |
| 密码 | BCrypt 加密存储，登录比对密文；`User.password` 用 `transient` 避免序列化 |
| 越权 | 列表强制归属过滤、详情可见性收口、写操作归属校验（403） |
| 并发 | 乐观锁 `version`（409） |
| 注入 | MyBatis `#{}` 预编译；Markdown 关闭 `html:true` |
| 跨域 | `app.cors.allowed-origins` 配置化，生产配真实域名（带凭证不配 `*`） |
| 配置 | 真实 `application.yml` 已 gitignore，密钥走环境变量（`JWT_SECRET` / `LLM_API_KEY` / `DB_PASSWORD`） |
