## 1. 项目介绍逐字稿

### 1.1 30 秒版（开场必背）

> 我做的是一个个人网站，主要用来展示学习成果和求职简历。它是一个完整的前后端分离项目：
> 前端 Vue 3 + TypeScript + Vite，后端 Spring Boot 4 + MyBatis + MySQL，一共 13 张表、30 个接口，
> 包含简历、笔记、用户三个核心模块，后来又加了讨论广场、笔记的 AI 分析，以及一个基于我自己笔记的 AI 知识库问答。
> 这个项目我是用 AI 辅助开发完成的，但在多用户场景下我做过一轮人工架构盘点，
> 修掉了 AI 生成代码里没有处理的越权问题——这也是我在这个项目里最有收获的部分。

**为什么这样讲**：30 秒内给出「规模数字 + 技术栈 + 模块 + 一个亮点钩子」，最后一句故意留口子让面试官追问越权的事，而那是你准备最充分的部分。

### 1.2 3 分钟版（让他深入问）

> **【背景】** 这个项目最初只是想把简历放到网上，后来逐步变成学习成果的展示站，最终做成了一个多用户的笔记 + 简历平台。
>
> **【架构】** 前后端分离。前端 Vue 3 组合式 API + TypeScript + Vite，状态用 Pinia，路由守卫做权限；
> 后端 Spring Boot 4 + MyBatis + MySQL 8，JWT 做鉴权，统一返回和全局异常处理。
> 数据层 13 张表，30 个接口。
>
> **【三个核心模块】** 简历模块支持多份简历增删改查和实时预览；笔记模块支持 Markdown、分类标签搜索；
> 用户模块做登录注册和个人资料。后来又加了讨论广场，笔记可以设为私有或公开到广场。
>
> **【AI 能力】** 两块：一是单篇笔记的 AI 分析（摘要/关键词/分类/知识点），走异步任务 + 轮询；
> 二是 AI 助手，基于我自己的笔记做知识库问答，也就是 RAG——用 MySQL 全文检索召回，
> 拼进 Prompt 交给大模型，回答会带上引用了哪几篇笔记。
>
> **【我踩过的坑】** 这个项目我全程用 AI 辅助开发，效率很高，但也出过真问题：
> AI 生成的后端代码默认不校验数据归属，多用户下会出现「A 看到 B 的笔记」。
> 是我后来做架构盘点时发现的，最后改成列表强制带 userId、详情统一在一个方法里做可见性收口才解决。
> 另外前端缓存只记「是否加载过」，换账号会串号，改成记 ownerId 才修好。
>
> **【现状】** 前端 23 条单测 + 后端 34 条 Service 层单测全绿，E2E 也补了 13 条业务用例，
> 部署脚本和 Nginx、systemd 配置都写好了，文档也完整，随时可以上线。

## 2. 岗位 A：VibeCoding / AI 辅助开发岗

### 2.1 讲法主线

**一句话定位**：我不是"让 AI 写代码"，我是**定架构、定约定、定验收标准，让 AI 在框里高效产出，我来把关边界**。

这条主线要贯穿全程。面试官真正想确认的是：
1. 你能不能把需求说清楚（提示词能力）
2. 你能不能判断 AI 产出对不对（代码审查能力）
3. 出问题了你知不知道怎么修（兜底能力）

### 2.2 你的真实协作证据（非常有说服力）

项目里有一份完整的提示词日志（`开发文档/2.使用的AI提示词.md`），展现了四个阶段：

| 阶段 | 工具 | 你在做什么 |
|---|---|---|
| 起步 | DeepSeek 对话 | 问"怎么建 Vue 项目"，让 AI 把简历模板转成页面 |
| 抽象 | DeepSeek | 主动要求"把三份简历的公共部分抽象成组件"——**你在主导架构，不是被动接受** |
| 规范化 | DeepSeek | 亲自定规范：组件统一 `Component` 后缀、样式三层分离、通用部分抽到 assets |
| 修补 | Cursor / Codex | 让 AI 检查布局问题、生成另外两份简历实体 |
| 全流程 | WorkBuddy | 从"整理接口 → 建 Spring Boot 工程 → 对接"整条链路交给 AI 完成 |

⚠️ 日志里有一句真实记录：「太逆天了，我什么都没做，直接一键把所有的代码全部写完了」。
**如果被问到"你是不是全靠 AI"**：不要回避，直接说——

> 对，第一版后端确实是一次性生成的，这也是我后来出问题的主要原因。
> 我当时没做多用户场景的审查，结果上线前盘点发现所有笔记查询都不带用户归属。
> 从那之后我的流程变了：**AI 出初稿之后，我一定会做一轮"场景级"审查**——
> 不问"代码能不能跑"，而是问"换成第二个人来用会怎样"。
> 这个项目里三个最严重的缺陷（越权、缓存串号、CORS 403）都是这么发现的。

**这段话的价值**：它证明你有自我迭代能力，而这是 VibeCoding 岗最看重的。

### 2.3 你的 AI 把关方法论（背下来，这是你的差异化）

1. **约定先行**：在让 AI 写之前先定死规范（组件后缀、样式分层、service 层抽象），
   这样 AI 产出天然可维护。本项目"页面永远不直连数据源，一律走 service 层"这条约定，
   让后来接后端时**页面和 store 零改动**——这是提前设计换来的。
2. **自动化验收**：AI 写完立刻跑 `vue-tsc` + `vitest` + `mvn test`，类型检查和 57 条用例是硬门槛。
3. **场景级人工评审**：重点看 AI 想不到的——多用户、并发、异常路径、权限边界。
4. **边界用例驱动**：写完权限改动，我补了 9 条权限用例（未登录入口显隐、重定向带来源）+ 4 条隔离用例（A/B 账号切换）。

### 2.4 VibeCoding 岗高频 10 问

| # | 问题 | 答题要点 |
|---|---|---|
| 1 | 你怎么给 AI 下需求？ | 给上下文（项目结构 + 已有约定）→ 给目标 → 给约束和反例 → 要求它先说方案再写代码。举例：我让 AI 抽象组件时，明确写了"组件带 Component 后缀、通用样式抽到 assets" |
| 2 | AI 生成的代码你怎么验证？ | 三层：类型检查 + 单测（自动）→ 接口脚本跑真实数据（端到端）→ 场景级人工评审（多用户/并发/异常） |
| 3 | AI 写的代码出过什么问题？ | 越权（不校验归属）、缓存串号（只记 loaded）、CORS 403（端口漂移）。三个都是"能跑但不对" |
| 4 | 你会完全信任 AI 的产出吗？ | 不会。AI 擅长"按需求生成"，不擅长"考虑谁不该看到什么"。安全和多租户边界必须人工审 |
| 5 | 用 AI 后你的效率提升多少？你怎么衡量？ | 举例：后端从零到 17 个接口打通，如果用传统方式要拆很多步；但要**加上审查成本**——我后期约 30% 时间在审查和修边界 |
| 6 | 你用过哪些 AI 工具？怎么选？ | DeepSeek（对话式设计/改样式）、Cursor（修补现有代码）、Codex/GPT-5.5（生成功能模块）、WorkBuddy（全流程工程化）。选择依据：改样式用快的、生成模块用上下文长的、跨文件重构用能看全局的 |
| 7 | AI 生成的代码可维护性怎么保证？ | 靠约定（命名/分层/样式）+ 文档（接口文档、设计文档同步更新）+ 测试。**约定是给 AI 的约束，也是给未来自己的** |
| 8 | 如果 AI 给的方案是错的怎么办？ | 举例：AI 一开始把 JWT 校验写在每个 Controller 里，我改成拦截器统一收口；可见性判断散落各处，我收口到一个 `assertVisible` |
| 9 | 你怎么防止 AI 写出安全漏洞？ | 明确写进提示词（"所有查询必须带 userId"）+ 代码审查清单（越权/注入/XSS/CORS/密钥）+ 权限测试用例 |
| 10 | VibeCoding 的局限是什么？ | AI 不知道你的业务边界和历史决策；长链路重构容易顾此失彼；它不会主动做"增量兼容"。所以人要做的是**架构决策和质量门禁** |

### 3.3 你的测试设计思维（这是面试核心，一定要讲）

**例子：权限测试的用例设计**（`auth-guard.spec.ts` 9 条）

不从"功能能不能用"出发，而是列**风险清单**再转用例：

1. 未登录时，页面上**不应该出现**编辑类文案（而不只是点了报错）
2. 点"写笔记"要弹登录提示，且**不能发起请求**（否则后端 401）
3. 弹窗"去登录"跳转后要**带上来源地址**（回跳体验）
4. 详情页非作者时，只保留 AI 分析入口，隐藏编辑/删除/置顶
5. `/notes`、`/profile`、`/assistant` 未登录必须重定向
6. 直接输 URL 访问编辑页也要被拦（不只靠按钮隐藏）

**例子：账号隔离测试**（`note-scope.spec.ts` 4 条）

1. A 登录后只拿到 A 的笔记
2. 同一浏览器切到 B，**不残留** A 的笔记（这条抓到了真实 bug：缓存串号）
3. 退出登录后清空上一位用户数据
4. 讨论广场不受登录切换影响（公开内容恒定）

> 这段讲出来，能证明你会**设计用例**，而不只是"写完跑一下"。

## 4. 通用技术追问（简短要点版）

### 前端

| 问题 | 要点 |
|---|---|
| 为什么用 Pinia 不用 Vuex？ | Vue 3 官方推荐，组合式写法，TS 友好，无 mutations 冗余 |
| 路由守卫怎么做权限？ | 三级：路由 `meta.requiresAuth` / 操作 `requireLogin()` / 展示 `isOwner` |
| 刷新页面登录态怎么恢复？ | `main.ts` 先 `await refresh()` 再挂路由（否则守卫先跑，误弹登录）；加 3s 超时兜底防白屏 |
| 前端怎么防止越权？ | 前端只做**体验**（隐藏按钮），真正的校验在后端；前端隐藏是必要的，但不能作为安全依据 |
| 为什么 `v-html` 有风险？ | XSS；本项目内容来自登录用户本人 + 样式收敛在 `.markdown-body` |

### 后端

| 问题 | 要点 |
|---|---|
| JWT 怎么设计的？ | 登录签发 → 前端 localStorage → 拦截器解析 userId → 写接口强制校验 |
| 为什么 GET 放行？ | 广场/详情需要游客可读；但 `/api/assistant/*` 这种 GET 要登录的，Controller 里手动判空抛 401 |
| 乐观锁怎么实现？ | `WHERE id=? AND version=?`，影响行数 0 即冲突；适合"编辑久、冲突少" |
| 为什么不用 `@Async`？ | 同类内部自调用绕过代理，注解失效；改用 TaskExecutor 显式提交 |
| 异步任务失败了怎么办？ | 落 `async_task` 表标记 failed + 记录原因；前端轮询拿到失败态给用户提示 |

### 数据库

| 问题 | 要点 |
|---|---|
| 为什么拆 `note_content`？ | 列表查询带 LONGTEXT 是性能陷阱 |
| 为什么用 JSON 存 tags？ | 初期灵活；后来要按标签统计就拆出 `tag` + `note_tag_rel`——JSON 用多了会长出真表 |
| 全文检索怎么做？ | FULLTEXT + ngram（`ngram_token_size=2`），**改配置后必须重建索引** |
| 13 张表怎么记？ | 按职责分组：主数据（user/note/resume）、正文（note_content）、标签（tag/note_tag_rel）、AI（note_analysis/async_task/chat_session/chat_message）、预留（note_share/file） |

## 5. 危险问题（容易答砸，提前准备）
