## 2. 前端层详解

### F1 · Vue 3 组合式 API

- **是什么**：`setup` 语法糖，`ref` / `computed` / `watch` / `onMounted` 直接在 `<script setup>` 里用
- **项目位置**：所有页面与组件；典型如 `AboutView.vue` 用 `computed` 由简历数据拼出时间线
- **关键点**：`computed` 有缓存，依赖不变不重算；`watch` 用于「监听用户切换重载数据」
- **坑**：`watch` 监听对象属性要写 getter 函数（`watch(() => userStore.profile?.id, ...)`），直接传对象监听不到内部变化
- **延伸**：`v-model` 在组件上的实现（`modelValue` + `emit('update:modelValue')`）

### F2 · TypeScript 严格模式

- **项目位置**：`tsconfig.app.json` 开了 `noUncheckedIndexedAccess`
- **含义**：`arr[0]` 的类型是 `T | undefined`，必须判空——这是故意加的约束，逼你处理边界
- **典型写法**：`const list = Object.values(store.resumes); return list[0] ?? fallback`
- **面试点**：为什么开严格模式？→ 把运行时的 `undefined` 错误提前到编译期

### F3 · Pinia + 缓存失效（本项目最有讲点的设计）

- **项目位置**：`stores/useNoteStore.ts` / `useResumeStore.ts`
- **核心问题**：只记 `loaded` 布尔值，换账号后列表会串号（显示上一个用户的数据）
- **解法**：记 **ownerId = 用户 id**，而不是"是否登录"
  - `useNoteStore.myNotesOwnerId` + `clearMyNotes()`
  - `useResumeStore.loadedFor: 'guest' | 'user'`
  - `watch(() => userStore.profile?.id)` 变化时强制重载，登出时清空
- **面试点**：这是「缓存与身份绑定」的典型陷阱，等同后端的"缓存 key 必须带用户维度"

### F4 · 路由守卫与三级权限

- **项目位置**：`router/index.ts`
- **三级**：
  1. 路由级：`meta.requiresAuth`（`/notes` `/profile` `/assistant`）→ 未登录跳登录页
  2. 操作级：`useAuthGuard().requireLogin()` → 未登录弹提示且**不发起请求**
  3. 展示级：`isOwner`（`note.authorId === userStore.profile.id`）→ 控制按钮显隐
- **坑**：给 `meta` 加自定义字段必须 `declare module 'vue-router'` 扩展 `RouteMeta`，否则 TS 报错
- **坑2**：`main.ts` 必须先 `await userStore.refresh()` 再 `app.use(router)`，否则刷新页面时守卫在登录态恢复前执行，已登录用户被误弹到登录页

### F5 · Vite 配置与代理

- **项目位置**：`vite.config.ts`
- **两件事**：
  1. `/api` 代理到 `http://localhost:8080`——开发期规避跨域
  2. `strictPort: true`——端口被占用直接报错，**不静默漂移**（漂移会导致 CORS 白名单失效，见 B10）
- **面试点**：开发代理只在开发环境生效，生产靠 Nginx 同源反代

### F6 · 组件与样式分层（项目硬约定）

- **约定**：组件名统一带 `Component` 后缀；样式三层——`global.css`（重置）/ `common/`（跨组件）/ `components/`+`views/`（专属）
- **规则**：用到两次以上的样式就往上抽一层
- **坑**：组件名不能是单个单词（ESLint `vue/multi-word-component-names`）

### F7 · Markdown 渲染

- **项目位置**：`MarkdownRendererComponent.vue`
- **链路**：markdown-it 解析 → highlight.js 高亮 → `v-html` 渲染
- **坑**：`v-html` 内容不受 scoped 样式影响，必须用全局样式 + `.markdown-body` 前缀收敛
- **坑2**：它是**孙组件**，在消息组件里改它的字号要用 `:deep(.markdown-body h1)`
- **安全点**：`v-html` 有 XSS 风险；本项目内容来自登录用户自己，风险可控，但要知道这个点

### F8 · HTTP 客户端封装

- **项目位置**：`utils/http.ts`
- **做了什么**：统一 `fetch` 封装；自动注入 `Authorization`；解包 `ApiResult<T>`（只返回 `data`）；401 自动清登录态
- **面试点**：为什么不直接用 axios？→ 依赖更少，且这层封装是"服务层抽象"的地基，换库只改一个文件

### F9 · 单元测试（Vitest）

- **现状**：23 条用例，3 个文件
  - `smoke.spec.ts`（10 条）：10 个页面能否渲染、未登录跳转
  - `auth-guard.spec.ts`（9 条）：未登录时的编辑入口显隐、点编辑弹登录提示、重定向带来源
  - `note-scope.spec.ts`（4 条）：A/B 账号切换后笔记不串号、登出清空、广场不受影响
- **技巧**：用 mock 拦截 `fetch`，模拟不同用户返回不同数据
- **坑**：登录提示弹窗是**模块级单例**，测试之间不会随组件卸载复位，用例开头要先关闭残留弹窗

### F10 · E2E（Cypress）

- **现状**：**只装了环境，没写业务用例**（`cypress/e2e/example.cy.ts` 是脚手架示例，断言的是 "You did it!"）
- **这是短板**，但面试时主动说出来 + 说清怎么补，比被发现好
- **补法**（建议 3 条起步）：注册→登录→写笔记→广场可见；私有笔记换账号访问 403；AI 助手提问拿到引用

## 3. 后端层详解

### B1 · 分层架构

`Controller`（参数校验、组装响应）→ `Service`（业务与权限）→ `Mapper`（SQL）
共 72 个 Java 类、6 个 Controller、8 个 Mapper XML。

### B2 · MyBatis 动态 SQL

- **坑**：`<if test="userId != null">` 这种"有值才加条件"的写法，在本项目里被**明令禁止**用于归属过滤
- 因为"没传 userId 就查全表"正是越权事故的根源；正确做法是缺失 userId 时走 `AND 1 = 0` 返回空集

### B3 · RESTful 设计

26 个接口，`/api/{模块}` 前缀；GET 读、POST 建、PUT 改、DELETE 删、PATCH 局部改。
详见 `3.接口文档.md`。

### B4 · JWT 鉴权

- **链路**：登录签发 → 前端存 localStorage（`user-token`）→ 每次请求带 `Authorization: Bearer xxx` → `JwtInterceptor` 解析出 userId 放进请求属性
- **规则**：GET 读接口公开；写接口 + `/api/auth/me` + `/api/users/**` 必须带令牌
- **坑**：拦截器对 GET 放行，所以 `/api/assistant/*`（GET）需要在 Controller 里**手动判空抛 401**
- **坑2**：`JWT_SECRET` 换了会让所有令牌失效（多机部署必须固定）

### B5 · BCrypt

`spring-security-crypto` 的 `BCryptPasswordEncoder`；存密文、比对密文，**永不明文存储**。
演示账号 `admin / 123456` 仅为本地便利——上线必改。

### B6 · 统一返回与异常处理

`ApiResult<T>{code,message,data}`，`code=0` 成功；`GlobalExceptionHandler` 把业务异常/参数异常/未知异常分别映射。

### B8 · 异步任务

- **选型**：`async_task` 表 + Spring 自动配置的 `TaskExecutor`
- **为什么不用 `@Async`**：同类内部自调用会绕过代理，注解失效——这是经典陷阱
- **流程**：提交任务 → 立即返回 taskId → 前端 1.5s 轮询（最多 40 次）→ 拿结果
- **演进**：将来换 MQ 消费者，前端轮询逻辑不用动

### B9 · 调用大模型（RestClient）

`LlmClient` 用 Spring 自带的 `RestClient` 调 DeepSeek（OpenAI 兼容 `/v1/chat/completions`）。
**坑**：Jackson 3 没有 `JsonNode`，解析响应必须用 `objectMapper.readValue(resp, Map.class)` + 标准 `java.util` 类型。

### B10 · CORS（本项目最痛的一个坑）

- **现象**：未登录一切正常，登录后所有请求 403
- **根因**：登录后请求带 `Authorization` → 触发 `OPTIONS` 预检 → Origin 不在白名单 → Spring 返回 403
- **叠加因素**：Vite 端口从 5180 漂移到 5181，白名单却写死 5180
- **修复**：白名单改 `http://localhost:*,http://127.0.0.1:*`；Vite 加 `strictPort`
- **教训**：**403 先怀疑预检，别急着查鉴权**

## 4. 数据层详解

### D2 · 大字段垂直拆分

`note` 存元数据（标题/状态/统计），`note_content` 存正文 LONGTEXT。
**原因**：列表查询带 LONGTEXT 是笔记类系统的典型性能陷阱。

### D3 · 乐观锁

`version` 字段，更新时 `WHERE id=? AND version=?`，影响行数 0 即冲突。
**为什么选它**：编辑停留时间长、冲突概率低，CAS 最省；不像悲观锁要持有事务锁。

### D5 · 全文检索（RAG 的召回层）

`note_content.ft_content` 建 FULLTEXT 索引；中文需要 `ngram_token_size=2`。
**坑**：配置改了必须**重建索引**，否则召回一直为空。
**选型**：几百篇笔记用 MySQL 全文检索足够，不引入向量库；将来只替换 `recall()` 方法。

### D7 · JSON 字段

`note.tags` 存 JSON 字符串、`resume.content` 整存 JSON。
**取舍**：省表、灵活，但**不能按内部字段查询/索引**——标签查询后来拆出了 `tag` + `note_tag_rel` 表，这就是"JSON 字段用多了会长出真表"的典型过程，面试很好讲。

### D8 · 迁移脚本

`schema.sql` 目前是**先 DROP 再 CREATE 的开发重构版**，生产必须改成增量迁移，并设 `spring.sql.init.mode=never`。

## 5. AI 层详解

### A1 · RAG 链路

```
用户提问 → 关键词召回（MySQL 全文检索，只检索自己的笔记）
        → 组装 Prompt（笔记片段 + 历史对话 + 问题）
        → DeepSeek 生成 → 落库 chat_message（refs 存引用溯源）
        → 前端渲染回答 + 「引用了 N 篇笔记」卡片
```

### A3 · Prompt 工程要点（项目里真实踩过的）

1. 强制 `response_format: json_object`，避免模型输出多余解释
2. **短追问（< 12 字）要拼上上一轮问题**再召回，否则"为什么？"召回不到任何东西
3. Prompt 要允许"参考笔记不相关时，依据历史对话作答"，否则模型会硬套不相关内容

### A5 · 降级

未配 `LLM_API_KEY` → 抛 `IllegalStateException` → 任务标记 failed 并记录原因，**不阻塞其他功能**。
这是"外部依赖必须有降级路径"的实践。

### A6 · AI 生成代码的把关（VibeCoding 核心能力）

见 `12.项目面试文档.md` 第 3 章——这是你投 VibeCoding 岗最能打的部分。

## 6. 工程与协作层

### E1 · Git

- **现状**：main / master / wjh 三个本地分支，`origin` 远端 **fetch 指向 gitee、push 指向 github**（配置异常，容易误推）
- **建议**：拆成 `gitee` / `github` 两个独立 remote

### E5 · 配置外置与密钥

- 真实 `application.yml` 被 `.gitignore` 排除，仓库只放 `application.yml.example`（占位符）
- 密钥走环境变量：`DB_PASSWORD` / `JWT_SECRET` / `LLM_API_KEY`
- **已验证**：全分支历史 0 命中真实配置文件

### E7 · 安全（面试必问"你考虑了哪些安全"）

| 层面 | 做法 |
|---|---|
| 越权 | 列表强制带 userId（缺失返回空集）；详情统一 `assertVisible` 收口 |
| 密码 | BCrypt 加盐哈希 |
| 注入 | MyBatis `#{}` 预编译，不用 `${}` 拼接 |
| XSS | `v-html` 仅用于自己内容，Markdown 渲染收敛在 `.markdown-body` |
| CORS | 白名单限定来源，生产覆盖成真实域名 |
| 配置 | 密钥不入库 |
| 隐私 | 公开仓库中手机号/邮箱已脱敏为示例值 |

### E8 · 开源仓库安全（真实事故）

项目推送到公开 GitHub 后，审计发现真实手机号/邮箱在 7 个文件里。已脱敏为示例值。
**教训**：公开仓库 ≠ 私有仓库，`.gitignore` 只管得住配置，管不住硬编码在代码/数据文件里的个人信息。
