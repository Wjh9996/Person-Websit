## P1 权限与数据隔离（最严重的一类）

### P1-1 用户 A 的笔记出现在用户 B 的页面上（P0）

**现象**：登录用户能在列表里看到别人写的笔记；点进去才被拦（"无权访问"）。

**根因（四个泄漏点，逐一排查出来的）**

| # | 位置 | 问题 |
|---|---|---|
| 1 | `NoteMapper.xml` `listNotes` | `user_id` 过滤写成 `<if test="userId != null">`，**userId 为空时退回查全表** |
| 2 | `noteService.fetchNotes(_query)` | 形参带下划线、**从不使用**，导致 userId 恒为空 |
| 3 | `NoteServiceImpl.getNote(id)` | **没有 userId、没有归属校验**，任何人拼 id 就能读全文 |
| 4 | `TagMapper.selectTagCounts` | 全站聚合，私有笔记的标签也外泄 |

**修复**

- 列表：`scope=mine` 必须带已鉴权 userId，缺失时 SQL 走 `AND 1 = 0` 返回空集（**绝不退回全表**）
- 详情：`NoteServiceImpl.assertVisible()` 统一收口——广场放行，私有必须作者本人，否则 `403 该笔记为私密笔记，仅作者可见`
- 标签云：按 scope 收口，游客只统计广场公开笔记
- 引入 `note.visibility`（0 私有 / 1 广场公开 / 2 链接分享预留），前端新增"发布到讨论广场"开关

**教训（通用）**
> ① 列表查询的归属条件**永远不要写成可选**——"没传用户就查全部"是越权最常见源头；
> ② 详情/写操作必须有独立的归属校验，不能只靠"列表里没出现就看不到"；
> ③ `_query` 这种"形参不用"的写法要零容忍，它被忽略了就没人发现 userId 一直是 null。

### P1-2 换账号后列表还是上一个人的数据（P0，前端缓存）

**现象**：同一浏览器 A 退出、B 登录，"我的笔记"仍显示 A 的笔记，打开才 403。

**根因**：`useNoteStore.myLoaded` 只是"加载过没"的布尔标记，**不判断数据属于谁**；
换账号后 store 认为已加载，直接跳过请求。

**修复**

- 新增 `myNotesOwnerId` 记录归属；`loadMyNotes()` 发现 owner 变了就强制重拉
- 未登录 / 401 时 `clearMyNotes()` 清空残留
- `watch(() => userStore.profile?.id)`：账号一切换（含登出）立刻失效缓存
- 同类问题：`useResumeStore` 只按 `'guest'/'user'` 记身份（A→B 都算 `'user'`），改为记**用户 id**

**教训**
> `loaded` 布尔标记不足以判断"数据是否还属于当前用户"。
> 任何按用户隔离的 store 都必须记 **ownerId = 用户 id**，而不是记"是否登录"。

## P2 联调与构建环境

### P2-1 登录后接口全部 403（CORS + 端口漂移）

**现象**：未登录一切正常，一登录就报 403。登录接口直接调却是好的。

**根因**：登录后 `http.ts` 给每个请求加 `Authorization` 头 → 请求不再"简单" → 浏览器先发 `OPTIONS` 预检；
而 Vite 在 5180 被占用时会**静默漂移到 5181**，后端 CORS 白名单写死 `http://localhost:5180` → 预检被拒 **403**。

**修复**

- CORS 默认白名单改为 `http://localhost:*,http://127.0.0.1:*`（实测端口通配符生效，`evil.com` 仍 403）
- `vite.config.ts` 加 `strictPort: true`：端口占用直接报错，不再静默漂移
- 新增 `scripts/start-dev.bat` 一键起服务

**教训**
> 跨域问题最容易伪装成 403/鉴权问题。**判断诀窍**：未登录正常、登录后失败 → 先怀疑请求头触发了预检。
> 生产环境必须用 `app.cors.allowed-origins` 覆盖成真实域名（带凭证时不能整体配 `*`）。

### P2-2 后端端口冲突（沙箱注入 4922）

**现象**：`Port 4922 was already in use`，服务起不来。

**根因**：执行环境会向 Java 进程注入 `server.port=4922`，而该端口已被占用。

**修复**：命令行参数优先级高于 system property——
`mvn.cmd spring-boot:run -Dspring-boot.run.arguments="--server.port=8080"`

### P2-3 Maven 拉不到 Spring Boot 快照

**现象**：`4.0.9-SNAPSHOT` 依赖解析失败。

**根因**：全局 `settings.xml` 的腾讯镜像 `<mirrorOf>*</mirrorOf>` 把快照仓库也代理了。

**修复**：改为 `*,!spring-snapshots`，放行 `repo.spring.io/snapshot`。

### P2-4 后台进程被回收导致"接口突然全挂"

**现象**：过一会儿前端请求全部失败。

**排查顺序**：`curl 8080` 是否通 → `netstat` 看端口 → `journalctl`/终端日志。
**缓解**：用 `scripts/start-dev.bat` 在独立窗口常驻；生产用 systemd `Restart=always`。

## P3 框架与数据

### P3-1 Jackson 3 包名变更（Spring Boot 4）

**现象**：`com.fasterxml.jackson` 全部报错；`@JsonIgnore` 直接找不到。

**根因**：SB 4 把 Jackson 升到 3.x，包名变 `tools.jackson`；**没有 `tools.jackson.annotation` 包**。

**修复**

- `ObjectMapper` → `tools.jackson.databind`；`TypeReference` → `tools.jackson.core.type`
- 不序列化密码改用 `transient` 字段，而非 `@JsonIgnore`
- web 依赖用 `spring-boot-starter-webmvc`（不是 3.x 的 `spring-boot-starter-web`）
- 解析大模型响应用 `objectMapper.readValue(resp, Map.class)` + 标准 `java.util` 类型（无 `JsonNode`）

### P3-2 消息顺序错乱（DATETIME 只到秒）

**现象**：AI 助手消息历史出现"问、问、答、答"。

**根因**：`created_at DATETIME` 默认精度到秒，同一秒内的消息 `ORDER BY` 结果不稳定。

**修复**：`ALTER TABLE chat_message MODIFY COLUMN created_at DATETIME(3)`（毫秒精度）。

### P3-3 全文检索没结果（ngram 未配）

**现象**：搜索/AI 召回永远为空。

**根因**：MySQL 中文全文检索需要 ngram 分词器，且必须**在建索引之前**配置 `ngram_token_size=2`。

**修复**：改 `my.cnf` → 重启 → **重建**全文索引。代码侧还加了 `LIKE` 兜底，保证索引不可用时功能不瘫。

### P3-4 数据库脚本会清空数据

**现象**：重启后数据没了。

**根因**：`schema.sql` 是开发版（开头 `DROP TABLE IF EXISTS`）+ `spring.sql.init.mode=always`。

**修复**：首次部署手工导入一次后立刻改成 `never`；后续变更走增量 ALTER。

## P4 AI 助手（RAG）

### P4-1 追问答"笔记里没有提到"

**现象**：第一轮回答正确，追问"再详细说说第二点"就答非所问或说没提到。

**根因**：短句本身检索不到东西；且 system prompt 要求"只能依据参考笔记"，堵死了基于上下文续答。

**修复**

- 问题 **< 12 字**且存在上一轮问题时，召回关键词拼成"上一轮问题 + 本轮问题"
- Prompt 放宽：参考笔记不相关但**历史对话**里有答案时，允许基于历史作答（须注明"依据上一轮对话"）
- 真正都没有时，不调模型，直接返回引导文案（省 token）

### P4-2 token 失控风险

**做法**：召回 Top5、单篇正文截断 2500 字、历史只带最近 6 条且每条截断 500 字；回答 `max_tokens=1500`。

### P4-3 scoped 样式改不动孙组件

**现象**：想改回答里 Markdown 的标题字号，普通选择器无效。

**根因**：`MarkdownRendererComponent` 是**孙组件**，其内部元素拿不到本组件的 scoped 标识。

**修复**：用 `:deep(.markdown-body h1)` 这类写法。

## 附录：排查路径（遇到"接口报错"按顺序走）

1. **分清是哪一层**：浏览器 DevTools → Network，看状态码与响应体 `code`
   - `code=401` → 未登录/令牌过期 → 重新登录
   - `code=403` → 越权或跨域预检 → 先确认 Origin 是否在白名单
   - `code=409` → 乐观锁冲突（笔记被人改过）→ 刷新重试
   - `code=0` 但 HTTP 500 → 后端异常，看日志
2. **确认服务活着**：`curl http://localhost:8080/api/notes?scope=plaza`
3. **确认代理通**：`curl http://localhost:5180/api/notes?scope=plaza`
4. **确认身份**：登录后请求是否带 `Authorization`（DevTools → Request Headers）
5. **看后端日志**：SQL 与异常栈都在终端 / `journalctl`
