# 部署上线方案：从本机开发到云服务器可访问

> 适用：一台云服务器跑「前端静态站点 + Spring Boot + MySQL」。
> 已配套的现成文件：`deploy/nginx.conf`、`deploy/interview-back.service`、`deploy/deploy.sh`。
> 与 `上线架构演进方案.md` 的分工：那份讲"为什么这么演进"，这份是**照着敲就能上线的操作手册**。

---

## 零、部署形态（先看清楚流量怎么走）

```
浏览器 → https://your-domain.com
            │
            ├─ /            → Nginx 直接返回 /opt/interview/front 的静态文件（含 SPA 回退）
            ├─ /assets/     → 带 hash 的静态资源，长缓存
            └─ /api/*       → 反代到 127.0.0.1:8080 的 Spring Boot → MySQL
```

**同源部署**：页面和接口都在 `https://your-domain.com` 下，浏览器不产生跨域，
所以线上**不需要配 CORS**（跨域白名单只在本地 dev 场景有意义）。

**配置建议**：2 核 4 G、40 G 磁盘起步（阿里云/腾讯云轻量即可），系统 Ubuntu 22.04 / Rocky 9 均可，
下面命令以 `apt` 为例，CentOS 系把 `apt install` 换成 `dnf install`。

---

## 一、服务器准备

```bash
# 1) 基础工具
sudo apt update && sudo apt install -y nginx git curl unzip

# 2) JDK 21（Spring Boot 4 要求 21+）
cd /opt && sudo curl -L -o jdk21.tar.gz \
  https://download.java.net/java/GA/jdk21.0.2/f2283984656d49d69e91c558476027ac/13/GPL/openjdk-21.0.2_linux-x64_bin.tar.gz
sudo tar -xzf jdk21.tar.gz && sudo mv jdk-21.0.2 jdk-21 && rm jdk21.tar.gz
/opt/jdk-21/bin/java -version

# 3) Node 22（只用于构建前端，构建完可以卸载）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # v22.x

# 4) 目录
sudo mkdir -p /opt/interview/{back,front,repo} /var/log/interview
sudo chown -R $USER:$USER /opt/interview /var/log/interview
```

云控制台**安全组**只需放行：`22`（SSH，建议改端口/密钥登录）、`80`、`443`。
**8080 不要对外暴露**，它只由本机 Nginx 反代访问。

## 二、MySQL 8 与 ngram 分词（搜索/召回依赖）

笔记搜索和 AI 助手召回都用 MySQL 全文索引 + ngram 分词器，**必须先配 `ngram_token_size=2`**：

```bash
sudo tee -a /etc/mysql/mysql.conf.d/mysqld.cnf > /dev/null <<'EOF'
[mysqld]
ngram_token_size=2
EOF
sudo systemctl restart mysql
mysql -uroot -p -e "SHOW VARIABLES LIKE 'ngram_token_size';"   # 应为 2
```

建库建用户（**不要用 root 跑应用**）：

```sql
CREATE DATABASE interview DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'interview'@'127.0.0.1' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON interview.* TO 'interview'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> ⚠️ ngram 必须在**建全文索引之前**配置好；若先建了索引再改参数，需要 `DROP INDEX` 后重建。

## 三、初始化表结构（关键：只做一次）

`back/InterViewBacked/src/main/resources/schema.sql` 是**开发版脚本，开头是 `DROP TABLE IF EXISTS`**，
所以**绝不能**让它在生产每次启动都跑一遍（会把数据清空）。

正确做法：

```bash
# 只在第一次部署时手工导入一次
mysql -uinterview -p interview < /opt/interview/repo/back/InterViewBacked/src/main/resources/schema.sql
```

导入后**必须**把配置改成不自动建表：

```yaml
spring:
  sql:
    init:
      mode: never      # 生产禁止 always，否则每次重启都会 DROP 重建
```

启动一次后端，`DataInitializer` 会幂等播种演示账号与示例数据（已有数据则跳过）。
验证：`curl http://127.0.0.1:8080/api/notes?scope=plaza` 能返回笔记即正常。

> 已经在线上跑起来后要改结构，走 `开发文档/4.数据库设计.md` 第七章的**增量 ALTER**，
> 不要重新导入 schema.sql。

## 四、部署后端（systemd 守护）

```bash
cd /opt/interview/repo/back/InterViewBacked
JAVA_HOME=/opt/jdk-21 ./mvnw -q -DskipTests clean package
cp target/*.jar /opt/interview/back/interview-backed.jar
```

放置服务单元（已写好，按实际域名/密码改）：

```bash
sudo cp deploy/interview-back.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now interview-back
journalctl -u interview-back -f      # 看启动日志
```

**生产必改的几项**（都在 systemd 的 `Environment=` 里，别写进配置文件，避免入库）：

| 变量 | 说明 |
|---|---|
| `JWT_SECRET` | `openssl rand -base64 48` 生成一个长随机串；**换了它所有已登录用户需重新登录** |
| `DB_PASSWORD` | 应用库用户密码 |
| `APP_CORS_ORIGINS` | 同源部署其实用不到，填真实域名即可 |
| `LLM_API_KEY` | 不配则 AI 分析/助手会失败（后端已做降级，不影响其他功能） |
| `-Xmx` | 1 G 内存机器建议 `-Xmx512m` 以内，给 MySQL 留空间 |

## 五、部署前端（Nginx 静态托管）

```bash
cd /opt/interview/repo/front/InterviewProjectProject
npm ci && npm run build      # 产出 dist/
sudo rm -rf /opt/interview/front && sudo cp -r dist /opt/interview/front
```

Nginx 配置：

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/interview.conf
sudo sed -i 's/your-domain.com/你的真实域名/g' /etc/nginx/conf.d/interview.conf
sudo nginx -t && sudo systemctl reload nginx
```

配置里已经处理好的三件事：
1. **SPA 回退**：`try_files $uri $uri/ /index.html`，否则刷新 `/plaza`、`/notes/xxx` 会 404；
2. **`/api/` 反代**到 8080，并透传 `X-Real-IP` / `X-Forwarded-Proto`；
3. **静态资源长缓存**：`dist/assets/` 文件名带 hash，可安全缓存一年。

## 六、HTTPS（必须有）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
# 自动续期
sudo systemctl enable --now certbot.timer
sudo certbot renew --dry-run
```

证书到期前 certbot 会自动续；Nginx 配置里的 `ssl_certificate` 由 certbot 维护，不要手改。

## 七、上线后必做的运维项

```bash
# 每日全量备份（保留 7 天）
0 3 * * * /usr/bin/mysqldump -uinterview -p'密码' interview | gzip > /data/backup/interview_$(date +\%F).sql.gz
0 4 * * * find /data/backup -name 'interview_*.sql.gz' -mtime +7 -delete
```

- **进程守护**：`Restart=always`，崩溃自动拉起；`systemctl status interview-back` 看状态
- **日志**：`/var/log/interview/back.log`（append 模式，需 logrotate 切割）
- **健康检查**：`curl -fsS http://127.0.0.1:8080/api/notes?scope=plaza`，可挂到云监控
- **更新发布**：`bash deploy/deploy.sh`（拉代码 → 打 jar → 构建前端 → 重启后端 → 接口自检）

## 八、上线前安全清单（必做，否则等于把后台交给陌生人）

代码仓库是**公开的**，下面这些默认值任何人都能看到，上线前必须逐个改掉：

| # | 项目 | 默认/现状 | 必须做的事 |
|---|---|---|---|
| 1 | **演示账号** | `admin / 123456`，写在 6 份文档和 `DataInitializer` 里 | 部署后**立即改密码**（或直接删掉重建账号），否则任何人可登录改你的笔记和简历 |
| 2 | **JWT 密钥** | 模板里是 `please-change-me-to-a-long-random-string` | `openssl rand -base64 48` 生成随机串，注入环境变量；**多机部署必须一致**，否则用户反复掉线 |
| 3 | **数据库账号** | 本地 root / `123456` | 线上建专用账号 `interview`，只给 `interview` 库权限；**不要复用本地密码** |
| 4 | **LLM API Key** | 走环境变量 `LLM_API_KEY` | 放 systemd `EnvironmentFile` 或容器 secret，**绝不写进仓库**（`application.yml` 已被 gitignore） |
| 5 | **CORS 白名单** | 默认 `http://localhost:*`（通配本地端口） | 线上用 `app.cors.allowed-origins` 覆盖成**真实域名**，不要留通配 |
| 6 | **建表脚本** | `schema.sql` 是先 DROP 再 CREATE | 确认 `spring.sql.init.mode=never`，否则每次重启清空数据 |
| 7 | **后端端口** | 8080 | 只监听 `127.0.0.1`，由 Nginx 反代，**不要公网暴露** |
| 8 | **个人信息** | 手机号/邮箱已在仓库脱敏为示例值 | 上线前确认简历页展示的联系方式，是你**愿意公开**的那个 |

> 第 1 条最容易被忽略：演示密码写进了文档，等于把钥匙贴在门上。

## 十、已知坑位速查

| 现象 | 原因与处理 |
|---|---|
| 搜索/AI 召回一直没结果 | 没配 `ngram_token_size=2`，或索引是在配置前建的 → 改配置后重建全文索引 |
| 刷新子页面 404 | Nginx 缺 `try_files ... /index.html` |
| 接口 502 | 后端没起来或端口不对：`systemctl status interview-back`、`journalctl -u interview-back -n 100` |
| 登录后立刻掉线 | 多台机器/重启后 `JWT_SECRET` 变了 → 固定密钥 |
| 重启后数据没了 | `spring.sql.init.mode=always` + 开发版 schema.sql 把表 DROP 重建了 |
| 页面能开但接口全 401 | 服务器时间偏差大导致令牌"未生效"；或令牌过期，重新登录 |
| AI 功能报错 | 未注入 `LLM_API_KEY`，或 DeepSeek 余额/网络问题；不影响其他模块 |
