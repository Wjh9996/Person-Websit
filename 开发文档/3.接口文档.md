# 个人网站前端接口与实体设计文档

> 整理自 `front/InterviewProjectProject/src/services/` 三个 service 层的真实函数签名。
> 用途：作为后端（Spring Boot + MyBatis）接口与表结构的设计依据。
> 约定：后端就绪后，只需替换 `src/services/` 三个文件的实现，页面与 store 无需改动。

## 一、总体约定

### 1.1 模块划分
| 模块 | 前端 service 文件 | 后端基路径 |
|------|-------------------|------------|
| 笔记 | `noteService.ts` | `/api/notes` |
| 用户 | `userService.ts` | `/api/auth`、`/api/users` |
| 简历 | `resumeService.ts` | `/api/resumes` |

### 1.2 统一返回结构
前端已定义 `ApiResult<T>`：
```ts
interface ApiResult<T> {
  code: number      // 0 成功，非 0 失败
  message: string   // 提示信息
  data: T           // 业务数据
}
```
后端所有接口统一用此结构包装（成功 `code=0`）。

### 1.3 认证方式（建议）
前端当前用 `localStorage` 存 `user-token`，后端建议改为 **JWT**：
- `POST /api/auth/login` 成功后在响应体 `data` 中返回 `token`，前端存 `localStorage`
- 后续请求在请求头携带 `Authorization: Bearer <token>`
- `getCurrentUser()`（`GET /api/auth/me`）凭 token 解析当前用户

### 1.4 时间格式
所有时间字段为 **ISO 8601 字符串**（如 `2026-08-21T00:00:00.000Z`），数据库建议用 `DATETIME`/`TIMESTAMP`，Java 端 `LocalDateTime` 序列化。

## 二、实体类（领域模型 & 数据库表）

### 2.1 Note 笔记
对应表 `note`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | String | 是 | 主键（建议 UUID / 雪花） |
| title | String | 是 | 标题 |
| summary | String | 否 | 列表摘要，空时由正文截取 |
| content | Text | 是 | Markdown 正文 |
| category | String | 是 | 分类 id（见 2.2 固定枚举） |
| tags | String(JSON) | 否 | 标签数组，建议存 JSON 字符串，或拆 `note_tag` 关联表 |
| pinned | Boolean | 是 | 是否置顶，默认 false |
| views | Integer | 是 | 阅读数，默认 0 |
| created_at | DateTime | 是 | 创建时间 |
| updated_at | DateTime | 是 | 更新时间 |

**前端类型**：
```ts
interface Note {
  id: string
  title: string
  summary: string
  content: string
  category: string      // 'frontend'|'backend'|'testing'|'tools'|'interview'
  tags: string[]
  pinned: boolean
  views: number
  createdAt: string
  updatedAt: string
}
type NoteDraft = Omit<Note, 'id' | 'views' | 'createdAt' | 'updatedAt'>
```

### 2.2 NoteCategory 笔记分类（固定字典）
前端目前是 `src/data/noteCategories.ts` 里的常量，**不通过接口下发**。建议后端也用固定枚举，或落地 `note_category` 字典表。

| id | label | icon |
|----|-------|------|
| frontend | 前端开发 | 🎨 |
| backend | 后端开发 | ⚙️ |
| testing | 软件测试 | 🧪 |
| tools | 工具链 | 🛠️ |
| interview | 面试准备 | 📚 |

### 2.3 User 用户
对应表 `user`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | String | 是 | 主键 |
| username | String | 是 | 登录账号，唯一 |
| password | String | 是 | 密码（**后端必须加密存储**，前端当前明文比对仅演示） |
| nickname | String | 否 | 昵称，默认同 username |
| email | String | 否 | 邮箱 |
| avatar | String | 否 | 头像（当前为占位字符，后续改 URL） |
| bio | String | 否 | 个人简介 |
| created_at | DateTime | 是 | 注册时间 |

**前端类型**：
```ts
interface User {
  id: string
  username: string
  nickname: string
  email: string
  avatar: string
  bio: string
  createdAt: string
}
interface LoginPayload { username: string; password: string }
interface RegisterPayload extends LoginPayload {
  nickname: string
  email: string
}
```

### 2.4 Resume 简历（嵌套结构，建议整存 JSON）
前端 `ResumeData` 为**深层嵌套对象**，结构不固定（数组项数量可变）。**不建议过度拆表**，统一存为一张 `resume` 表，正文用 JSON 列（MySQL 5.7+ 的 `JSON` 类型或 `LONGTEXT`）保存整份 `ResumeData`。

对应表 `resume`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | String | 是 | 主键（如 `custom-<时间戳>`） |
| label | String | 是 | 导航标题（= basicInfo.title 或 name） |
| path | String | 是 | 路由路径，如 `/resume/custom-xxx` |
| icon | String | 否 | 导航图标，默认 📄 |
| content | JSON/Text | 是 | 整份 ResumeData 序列化 |
| created_at | DateTime | 否 | 创建时间 |
| updated_at | DateTime | 否 | 更新时间 |

**前端类型**（存入 `content`）：
```ts
interface ResumeData {
  basicInfo: { name: string; title: string; phone?: string; email?: string }
  education: { school: string; major: string; period: string }
  summary: string[]
  campus: Array<{ period: string; description: string }>
  skills: string[]
  internships: Array<{ company: string; position: string; period: string; duties: string[] }>
  projects: Array<{ name: string; techStack: string; description: string; duties: string[] }>
  projectDutyTitle?: string
}
interface ResumeNavItem { id: string; label: string; path: string; icon: string }
// 快照结构
interface ResumeSnapshot {
  resumes: Record<string, ResumeData>   // key = id
  navItems: ResumeNavItem[]
}
```

## 三、接口清单

### 3.1 笔记模块 `/api/notes`

| # | 方法 | 路径 | 前端函数 | 请求 | 响应 |
|---|------|------|----------|------|------|
| 1 | GET | `/api/notes` | `fetchNotes(scope)` | Query: `scope=`（`mine`\|`plaza`，默认 `plaza`）、`keyword?`、`category?`、`tag?` | `Note[]`（置顶优先、按更新时间倒序） |
| 2 | GET | `/api/notes/{id}` | `fetchNoteById(id)` | 路径 id | `Note` 或 `null`；**私有笔记非作者返回 403** |
| 3 | POST | `/api/notes` | `createNote(draft)` | Body: `NoteDraft`（含 `toPlaza`） | `Note`（含生成的 id/time） |
| 4 | PUT | `/api/notes/{id}` | `updateNote(id, draft)` | 路径 id + Body: `NoteDraft`（`toPlaza` 不传表示不改动可见性） | `Note` 或 `null` |
| 5 | DELETE | `/api/notes/{id}` | `deleteNote(id)` | 路径 id | `boolean`（删除成功 true） |
| 6 | PATCH | `/api/notes/{id}/pin` | `togglePinned(id)` | 路径 id | `Note`（返回切换后对象） |
| 7 | PATCH | `/api/notes/{id}/views` | `increaseViews(id)` | 路径 id | `void`（阅读数 +1） |
| 8 | GET | `/api/notes/tags` | `fetchAllTags(scope)` | Query: `scope=`（同列表） | `Array<{ tag: string; count: number }>`（按 count 倒序） |
| 9 | PATCH | `/api/notes/{id}/plaza` | `togglePlaza(id, toPlaza)` | 路径 id + Query: `toPlaza=true\|false` | `Note`（含切换后的 visibility） |

> 说明：前端 `resetNotes()` 为演示重置，可不提供后端接口。
> 列表筛选目前在前端 computed 完成（见 `useNoteStore.filteredNotes`），后端按 Query 参数做服务端过滤即可，暂不需要分页（数据量小）。

#### 3.1.1 可见性约定（讨论广场）

| 字段 / 参数 | 含义 |
|---|---|
| `Note.visibility` | `0` 私有（仅作者可见）、`1` 讨论广场公开（所有人可见），预留 `2` 链接分享 |
| `NoteDraft.toPlaza` | 创建/更新时是否发布到广场；更新时不传代表保持原可见性 |
| `scope=mine` | 我的笔记：需登录，后端按 JWT 取当前用户，绝不返回他人笔记 |
| `scope=plaza` | 讨论广场：公开，后端固定过滤 `visibility = 1` 并 JOIN 出作者昵称 |

安全约束（修复「A 的笔记出现在 B 的页面」）：
- `NoteMapper.listNotes` 的 `user_id` 过滤是**必须的**，缺失时走 `AND 1 = 0` 返回空集，不再退化成查全表；
- 详情接口 `GET /api/notes/{id}` 由 `NoteServiceImpl.assertVisible` 收口：广场笔记放行，私有笔记必须作者本人，否则 `403 该笔记为私密笔记，仅作者可见`；
- 标签云同理：`scope=mine` 只统计本人标签，游客（`scope=plaza`）只统计公开笔记的标签。

### 3.4 AI 助手（基于自己笔记的知识库问答）`/api/assistant`

| # | 方法 | 路径 | 前端函数 | 请求 | 响应 |
|---|------|------|----------|------|------|
| 1 | GET | `/api/assistant/sessions` | `fetchSessions()` | 凭 token | `ChatSession[]`（按更新时间倒序） |
| 2 | POST | `/api/assistant/sessions` | `createSession(title?)` | Body: `{title?}` | `ChatSession` |
| 3 | DELETE | `/api/assistant/sessions/{id}` | `deleteSession(id)` | 路径 id | `boolean` |
| 4 | GET | `/api/assistant/sessions/{id}/messages` | `fetchMessages(sessionId)` | 路径 id | `ChatMessage[]`（按时间正序） |
| 5 | POST | `/api/assistant/sessions/{id}/ask` | `askQuestion(sessionId, question)` | Body: `{question}` | `AskResult{answer, refs, fromKnowledgeBase}` |

说明：

- **全部接口都要求登录**。GET 由 `JwtInterceptor` 放行，因此 Controller 用
  `@RequestAttribute(value="userId", required=false)` 取身份后手动判空，未登录返回 `401 请先登录后再使用 AI 助手`。
- 会话与消息都校验 `user_id` 归属，越权访问返回 `403 无权访问他人会话`。
- 召回只在**当前用户自己的笔记**里做（`WHERE n.user_id = ?`），引用来源随回答一起返回，
  前端渲染成可点回原文的 chips。详见 `开发文档/6.AI助手知识库问答设计.md`。
