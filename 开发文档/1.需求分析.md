## 附一：上线与多用户化待解决的问题（2026-09-03 架构盘点）

以下问题由代码实际盘点得出，是「从个人站转向多用户在线系统」前必须先解决的，
按优先级排列。详细方案见 `开发文档/上线架构演进方案.md`。

### P0 · 数据归属缺失（水平越权，最严重）

- `note` / `resume` 表**均无 `user_id` 字段**
- `JwtInterceptor` 已解析出 `userId`，但只有 `UserController`、`AuthController` 使用，
  `NoteController` / `ResumeController` **完全未用**
- 后果：`NoteServiceImpl` 与 `ResumeServiceImpl.getSnapshot()` 使用 `selectAll()`
  返回全库数据；`save` / `delete` 不校验归属，任何登录用户可改、删他人内容

### P0 · 并发编辑静默覆盖

- `note` / `resume` 表**均无 `version`**；保存逻辑是「先查 → 全量覆盖 → update」
- 典型 lost update：后提交者整份覆盖先提交者，且没有任何提示

### P0 · 笔记列表查询带出全文（性能）

- `NoteMapper.xml` 的 `columns` 片段包含 `content`(LONGTEXT)，
  `selectAll` 会把全部笔记正文一次性查出
- 用户量上升后，带宽与内存开销急剧放大，是笔记类系统的典型陷阱

### P0 / P1 · 安全与运维缺口

- 无登录限流、无 HTTPS、CORS 硬编码 `localhost:5180`
- 无数据库自动备份、无健康检查 / 监控、JWT 无吊销机制

> 以上问题**尚未修改代码**，仅记录待办。
