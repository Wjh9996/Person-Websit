## 3. 第一阶段：初步设计

### 3.1 需求分析

原始需求很朴素，就三条：

1. **简历展示**：把简历放到网页上
2. **编辑简历**：能在线改
3. **公网访问**：最终要部署出去

后续扩展为三模块（简历 / 笔记 / 用户）并追加两项 AI 能力。
需求阶段还做了一次**架构盘点**，直接把"从个人站转向多用户系统"的隐患列成 P0 待办——
这一步很关键，它决定了后面重构的顺序：

- P0 数据归属缺失（水平越权）
- P0 并发编辑静默覆盖（无 version）
- P0 列表查询带出全文（性能陷阱）
- P0/P1 无限流、无 HTTPS、CORS 硬编码、无备份

### 3.2 技术选型与取舍

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript | 组合式 API + 类型安全，单兵开发效率最高 |
| 构建 | Vite | 冷启动快、`/api` 代理天然解决开发跨域 |
| 状态 | Pinia（setup 写法） | 比 Vuex 轻量，TS 友好 |
| 后端 | Spring Boot 4 + MyBatis | 生态成熟；MyBatis 手写 SQL，便于控制"归属过滤"这类关键条件 |
| 数据库 | MySQL 8 | 已有基础；**ngram 全文检索**能直接支撑搜索与 AI 召回 |
| 鉴权 | JWT（无状态） | 应用无状态，未来水平扩展不用改会话 |
| 大模型 | DeepSeek（OpenAI 兼容） | 一个 `RestClient` 就能调，不用引 SDK |
| **不引入** | Redis / MQ / 分布式 | 量级（数十人）用不上，引入反而带来缓存一致性、消息幂等等复杂度 |

> 这一条"**为什么不用 Redis/MQ**"是本项目最值得讲的取舍：先保证正确性与简单，规模真的上来了再演进。

### 3.3 接口契约先行

在没有后端时先写 `3.接口文档.md`，把**前端需要什么数据**定义清楚：

- 统一包装 `ApiResult<T>{code, message, data}`，`code=0` 成功
- 前端 service 方法签名与后端一一对应（note / resume / user 三组）
- 后来扩展到 **28 个接口**：笔记 9、分析 3、AI 助手 5、用户 5、简历 4

好处在对接阶段兑现：**只替换 service 实现，页面和 store 一行没改**。

### 3.4 数据模型设计（v1 → v2）

| 版本 | 形态 | 问题 |
|---|---|---|
| v1 | `user` / `note`(含正文) / `resume`(JSON) 三表 | 无归属、无版本、正文跟着列表查 |
| v2 | 13 张表 | 见下 |

v2 的关键改动：

- **归属**：`note` / `resume` 加 `user_id`，所有查询强制带
- **并发**：加 `version` 乐观锁；加 `content_hash` 做内容去重（无变化不写库）
- **性能**：`note_content` 垂直拆分，列表只查元数据，详情/AI 才取正文
- **规范**：`tag` + `note_tag_rel` 做标签真相源（`note.tags` 仅作展示冗余）
- **扩展**：`note_share`、`note_analysis`、`async_task`、`file` 预留
- **AI 助手**：`chat_session` / `chat_message`（`refs` 存引用溯源）
- **检索**：`note_content` 加 ngram 全文索引

### 3.5 工程约定（硬性，必须遵守）

**前端**
1. 组件文件名带 `Component` 后缀
2. 样式三层分离：`global.css` → `common/` → `components/`；复用两次以上就往上抽
3. `<script lang="ts">`；组件名多单词
4. 页面**永不直接 `import src/data/`**，一律走 `src/services/`
5. 权限收口走守卫（路由 `meta.requiresAuth` + `useAuthGuard`），不各处写 if

**后端**
1. Controller → Service → Mapper 分层，统一 `ApiResult<T>`
2. 列表查询的归属条件**必须写死**，不允许"没传 userId 就查全部"
3. 写操作与私有数据读取必须校验归属
4. 异步走 `async_task` + `TaskExecutor`（不用 `@Async`，避免自调用代理失效）

## 4. 第二阶段：具体实现

### 4.1 前端第一版（无后端）

搭 Vue 工程 → 全局布局（Header/Footer）→ 三大模块页面 → 抽 service 层（先落 localStorage）
→ Markdown 渲染与目录 → 分类/标签/搜索/置顶等交互。

**最关键的一个决策**：service 层抽象。当时数据只是内存/localStorage，但接口按"将来要换成 HTTP"来设计（返回 Promise）。后面接后端时验证了价值——**页面与 store 零改动**。

### 4.2 后端搭建与合并

- Spring Boot 4 + MyBatis + MySQL，包名 `com.wjh.interviewbacked`
- 适配 SB4 差异：web 依赖用 `spring-boot-starter-webmvc`；**Jackson 升到 3.x**（包名 `tools.jackson`，且没有 `tools.jackson.annotation`，`@JsonIgnore` 用不了 → 密码改 `transient`）
- Maven 镜像拦截快照：腾讯镜像 `<mirrorOf>*</mirrorOf>` 会拦 SB 快照 → 改 `*,!spring-snapshots`
- JDK 21；沙箱会注入 `server.port=4922` → 启动必须显式 `--server.port=8080`

### 4.3 前后端对接

- `utils/http.ts`：注入 JWT、解包 `ApiResult`、`code!==0` 抛 `ApiError`、401 清登录态
- `vite.config.ts` 配 `/api` 代理到 8080（开发环境零跨域）
- `main.ts` **先 `await userStore.refresh()` 再挂载路由**，否则刷新页面时守卫先于登录态恢复执行，会把已登录用户误弹到登录页（加了 3 秒超时兜底）

### 4.4 数据库重构 v2

按 §3.4 执行；`schema.sql` 写成"DROP + CREATE"的**开发重建脚本**，
`4.数据库设计.md` 另附**生产增量 ALTER 方案**（禁止线上直接跑开发脚本）。

### 4.5 多用户隔离与讨论广场

这是本项目**改动最大、也最有价值**的一段：

1. 引入 `note.visibility`（0 私有 / 1 广场公开 / 2 链接分享预留）
2. 列表分 `scope=mine`（本人，需登录）与 `scope=plaza`（公开，过滤 `visibility=1` 并 JOIN 作者昵称）
3. 详情统一走 `assertVisible()` 收口
4. 标签云、首页统计同步按 scope 收口
5. 前端 store 拆成 `myNotes` / `plazaNotes` + `setScope()`
6. 新增 `/plaza` 页面、`/notes` 改为需登录；编辑器加"发布到讨论广场"开关

期间修了两个真实问题（详见 `8.问题总结与排查手册.md` P1）：

- **越权**：列表在 userId 为空时退回查全表、详情无归属校验 —— 后端收口
- **缓存串号**：换账号后列表仍是上一个人的 —— 前端加 `ownerId` + `watch(profile.id)` 失效机制

### 4.6 AI 分析模块

- 4 种分析类型（摘要 / 关键词 / 分类建议 / 知识点），DeepSeek 强制 `response_format: json_object`
- 异步：`async_task` + `TaskExecutor`，前端 1.5s × 40 轮询
- 正文变更（`content_hash`）自动把旧分析置为失效

### 4.7 AI 助手（RAG）

- 链路：提问 → 落库 → **全文检索召回 Top5（仅自己笔记）** → 拼 Prompt → DeepSeek → 落库带引用
- 选型：MySQL 全文检索而非向量库（量级够用、零新增组件；将来只换 `recall()`）
- 多轮会话持久化（`chat_session` / `chat_message`），回答带引用卡片可点回原文
- 实测修的两个体验坑：消息乱序（改 `DATETIME(3)`）、追问召回跑偏（短句拼接上一轮问题 + Prompt 放宽）

### 4.8 体验打磨

AI 助手页改成 DeepSeek 风格：侧栏会话 + 居中 780px 对话区、提问右气泡、回答整段铺开（Markdown）、
思考计时、底部大圆角输入框、空态推荐问题。

## 5. 第三阶段：部署上线

### 5.1 部署形态与规格

```
浏览器 → https://domain
          ├─ /、/assets/  → Nginx 静态文件（dist）
          └─ /api/*       → 反代 127.0.0.1:8080 → MySQL
```

同源部署 ⇒ **线上不需要 CORS**。建议 2 核 4G 起步；安全组只开 22/80/443，**8080 不对外**。

### 5.2 环境准备

- JDK 21（SB4 要求）、Node 22（仅构建）、Nginx、Git
- MySQL 8：必须先配 `ngram_token_size=2` 并**在建全文索引之前**完成，否则索引无效
- 建独立应用账号（`interview`），不要用 root 跑应用

### 5.3 数据库初始化（最容易出事的一步）

```bash
# 只在第一次部署时手工导入一次
mysql -uinterview -p interview < schema.sql
```

然后**必须**确认：

```yaml
spring:
  sql:
    init:
      mode: never   # 绝不能是 always：schema.sql 开头是 DROP TABLE，会把数据清空
```

> 之后所有结构变更走 `4.数据库设计.md` 的增量 ALTER，不重新导入。

### 5.4 后端部署

```bash
mvnw -q -DskipTests clean package
cp target/*.jar /opt/interview/back/interview-backed.jar
cp deploy/interview-back.service /etc/systemd/system/
systemctl enable --now interview-back
```

生产必改：`JWT_SECRET`（换了全员掉线，首次就定好）、`DB_PASSWORD`、`APP_CORS_ORIGINS`、`LLM_API_KEY`、
`-Xmx`（小机器留内存给 MySQL）。密钥全部走 systemd 的 `Environment=`，不落配置文件。

### 5.5 前端部署

```bash
npm ci && npm run build
cp -r dist /opt/interview/front
cp deploy/nginx.conf /etc/nginx/conf.d/interview.conf   # 改域名
nginx -t && systemctl reload nginx
```

Nginx 里已处理好三件事：**SPA 回退**（`try_files ... /index.html`，否则刷新子路由 404）、
`/api` 反代（透传真实 IP 与协议）、静态资源长缓存（`assets/` 文件名带 hash）。

### 5.6 HTTPS

```bash
certbot --nginx -d your-domain.com -d www.your-domain.com
systemctl enable --now certbot.timer   # 自动续期
```

### 5.7 运维

mysqldump 每日备份（保留 7 天）、`Restart=always` 进程守护、日志轮转、
健康检查 `curl /api/notes?scope=plaza`、更新用 `deploy/deploy.sh`。

### 5.8 上线验证清单

- [ ] 首页/广场/详情/简历正常；**刷新子路由不 404**
- [ ] 未登录只能浏览；直接访问 `/notes`、`/profile`、`/assistant` 跳登录
- [ ] 换第二个账号验证：看不到第一个账号的笔记，打开他人私有笔记 403
- [ ] AI 助手能召回并给出引用（无 Key 时失败属预期）
- [ ] `spring.sql.init.mode=never` 已确认
- [ ] 8080 未暴露；HTTPS 可访问且 HTTP 自动跳转

## 6. 关键决策记录（ADR 摘要）

| # | 决策 | 备选 | 选择理由 |
|---|---|---|---|
| A1 | 页面只通过 service 取数 | 组件直接引数据模块 | 后端接入时页面/store 零改动（已验证） |
| A2 | 列表归属条件写死 | userId 为空就查全部 | 后者是越权根源，实测出过事故 |
| A3 | 乐观锁 version | 悲观锁 / 最后写入胜出 | 编辑停留长、冲突少，CAS 成本最低 |
| A4 | 正文垂直拆分 | 列表直接查 LONGTEXT | 用户量上来后带宽/内存是致命的 |
| A5 | 异步用 TaskExecutor | `@Async` | `@Async` 自调用会代理失效 |
| A6 | RAG 用全文检索 | Embedding 向量库 | 几百篇笔记够用、零新增组件；将来可换 `recall()` |
| A7 | 讨论广场用 visibility 字段 | 单独一张广场表 | 一个字段足够，且预留了链接分享态 |
| A8 | store 记 ownerId | 只记 loaded | 换账号不重载会串号（实测出过问题） |
| A9 | 不引入 Redis/MQ | 提前上中间件 | 量级不需要，复杂度是负债 |
| A10 | 同源部署 | 前后端分离域名 | 免跨域，配置最少 |

## 7. 教训与坑（浓缩版，详见 `8.问题总结与排查手册.md`）

| 类别 | 代表问题 | 一句话教训 |
|---|---|---|
| 权限 | 列表退回全表、详情无校验 | 归属条件永不为可选项 |
| 缓存 | 换账号列表仍是旧数据 | `loaded` 不够，要记 `ownerId` |
| 联调 | 登录后请求全 403 | 未登录正常、登录后失败 → 先怀疑跨域预检 |
| 框架 | Jackson 3 包名、`@JsonIgnore` 不存在 | SB4 升级要按新包名排查 |
| 数据 | 消息乱序、全文检索无结果 | `DATETIME(3)`；ngram 必须在建索引前配 |
| 部署 | 重启丢数据、刷新 404 | `sql.init.mode=never`；Nginx 加 SPA 回退 |
